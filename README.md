# i记账

一个**纯本地**的 Android 记账 App：监听支付通知，自动记账，不用手动输入。

数据只存在你自己的手机里，**App 没有任何联网权限**。

---

## 为什么做这个

市面上的记账 App 要么要你手动记每一笔，要么把数据传到云端。

i记账 的做法是：Android 有个「通知使用权」，授权一次之后，微信、支付宝、美团付款成功时发的通知，它就能读到，然后自动解析出**金额、商户、时间、收支方向**，记进本地数据库。

**你只管付钱，账自己就记上了。**

---

## 功能

### 自动记账
- 监听 12 个 App 的支付通知

| 支付宝 | 微信 | 淘宝 | 京东 | 拼多多 | 闲鱼 |
|---|---|---|---|---|---|
| 美团 | 大众点评 | 闪送 | 小红书 | 抖音 | 今日头条 |

- **金额解析**：语义引导词优先（实付、实收、付款金额），其次货币符号，再次「X.XX 元」，**绝不裸抓数字**（否则会把订单号、余额、百分比当成金额）
- **广告过滤**：支付宝常发「你有一笔 0.08 元的支出，领 1 元生活缴费红包」这类诱导文案，命中营销词且没有成交确认词时整笔丢弃
- **分类打分制**：每个分类有一组带权重的词（强信号 10 / 品牌 8 / 品类 6 / 后缀 3），另有排除词一票否决。所以「某某餐饮管理有限公司买手机」会判成数码，而不是餐饮
- **隐私脱敏**：通知原文里的手机号、银行卡号、身份证，入库前替换成 `[手机号]` 等形式

### 记账与管理
- 手动记账、编辑、删除
- 每笔可查看**原始通知原文**，核对是哪个 App 的哪条通知记的
- 分类：支出 11 类（餐饮/购物/交通/跑腿快递/通讯/娱乐/医疗/住房/日用/教育/人情/宠物/数码/转账/其他）、收入 8 类（经营/转账/工资/红包/退款/理财/报销/其他）

### 统计
- 按 **日 / 周 / 月 / 年** 切换，左右翻页
- 分类占比环形图 + 排行
- 收入与支出分开统计

### 稳定性
- **前台保活服务**（可选开启）：三星等系统会清理后台，一旦进程被杀，通知监听会被系统解绑且**不会自动恢复**——于是你以为在记账，其实早就漏了。开启后常驻一条通知，让系统别杀进程

## 权限说明

| 权限 | 用途 |
|---|---|
| **通知使用权**（BIND_NOTIFICATION_LISTENER_SERVICE） | 读支付通知，这是核心功能。需要你在系统设置里手动授权一次 |
| `POST_NOTIFICATIONS` | 显示保活服务的常驻通知（Android 13+） |
| `FOREGROUND_SERVICE` / `_SPECIAL_USE` | 前台保活服务 |

**没有 `INTERNET` 权限**——装好后可以在系统权限里核对，App 连不上任何服务器。

## 编译

环境要求：

- JDK 21（`brew install openjdk@21`）
- Android SDK，`compileSdk = 36`、`build-tools 36.0.0`
- Gradle 用仓库自带的 wrapper（8.11.1），不用另装

```bash
git clone git@github.com:XXKG2026/i-accounting.git
cd i-accounting

# local.properties 不在仓库里，需要自己建一行
echo "sdk.dir=$HOME/Android/sdk" > local.properties

export JAVA_HOME=/opt/homebrew/opt/openjdk@21
export ANDROID_HOME=$HOME/Android/sdk

./gradlew assembleDebug          # 产物：app/build/outputs/apk/debug/app-debug.apk
./gradlew testDebugUnitTest      # 跑单元测试
```

## 安装与首次使用

1. 装上 APK
2. 打开 App → 设置 → 点「去开启」→ 在系统列表里把 **i记账** 打开
3. 回到 App，设置页的「通知读取权限」应显示**已开启**
4. 建议打开「后台保活」
5. 付一笔钱试试，看首页是否出现记录


## 测试

```bash
./gradlew testDebugUnitTest
```

46 个用例，覆盖：

- 正常的支出/收入识别
- 余额不要被当成消费金额（「余额 ¥500，实付 ¥20」必须记 20）
- 百分比不要被当成金额（「优惠 12.50%」）
- 订单号不要被当成金额
- 广告通知要丢弃，但**带成交确认词的真交易不能被误杀**
- 分类：退款优先于经营（退款的文案里也有"订单""商品"）
- 分类：商家收款 → 经营，个人收到转账 → 转账
- 打分制的确定性（同一文本跑 20 次结果一致）
- 脱敏正则不误伤金额和订单号

## 已知限制

这些不是 bug，是 Android 系统的硬限制：

| 限制 | 说明 |
|---|---|
| **扫码收款抓不到** | 微信/支付宝从 2020 年起，扫码**收款**不再发系统通知（改成 App 内消息 + 语音播报）。所以顾客扫你码付的钱，没有通知可解析 |
| 部分通知没金额 | 有些通知只写「你有一笔消费，点此查看详情」，正文里没有数字 |
| App 被杀会漏记 | 已提供保活开关降低概率，但不能 100% 保证 |
| 跳转银行 App 付款 | 支付在银行侧完成，支付类 App 不发通知 |
| 一单多笔 | 拆单支付时可能只记到一笔 |
| 退款需人工确认 | 退款通知格式多样，偶尔会漏 |

## 隐私

- 所有数据存在 App 私有目录的 SQLite 里
- **App 没有联网权限**，代码里没有任何 HTTP 请求
- 通知原文入库前脱敏（手机号 / 银行卡 / 身份证）
- 卸载 App 等于彻底删除数据，没有云端副本
